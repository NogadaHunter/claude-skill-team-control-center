# Claude Skill Team Control Center

Claude Code에 등록한 직원(서브에이전트, `~/.claude/agents/*.md`)과 스킬이 **지금 무엇을 하고, 그동안 얼마나 일했고, 토큰·비용을 얼마나 썼는지** 한 화면에서 보고, 더 잘 운영하기 위한 제언까지 받는 로컬 대시보드다.
이 PC의 Claude Code 대화 기록(`~/.claude/projects`)을 **읽기만** 하고, 서버는 `127.0.0.1`(이 컴퓨터)에서만 열린다. 외부로 아무것도 보내지 않는다.

## 경로와 명령

- 이 스킬 폴더를 `SKILL_DIR`이라 부른다(스킬을 불러올 때 알려 주는 Base directory).
- 모든 조작은 하나의 도구로 한다:

```bash
node "SKILL_DIR/app/scripts/ctl.mjs" <명령> [옵션]
```

- 서버가 꺼져 있으면 명령이 알아서 켠다(처음이면 설정부터 만든다). 서버는 창을 닫아도 계속 돌고, `stop`으로 끈다.
- 대시보드 주소: http://127.0.0.1:4790 (포트가 겹치면 명령 앞에 `PORT=4791` 같은 환경 변수를 준다)

## 처음 설치할 때

1. `node -v`로 Node.js 18 이상인지 확인한다. 없거나 낮으면 https://nodejs.org 에서 LTS를 설치하라고 안내하고 멈춘다.
2. `ctl.mjs doctor`로 환경을 점검해 결과를 짧게 전한다(직원 수, 대화 기록, PDF용 브라우저).
3. 사용자에게 **화면에서 자신을 부를 이름**을 한 번 묻는다(예: 대표님, 팀장님, 나 — 모르면 '사용자'). 스킬 DB 엑셀(SkillDB 표가 있는 현황관리 엑셀)을 쓰는지도 묻는다(없으면 설치된 스킬 목록을 자동으로 쓴다).
4. 설정을 만든다:
   ```bash
   node "SKILL_DIR/app/scripts/ctl.mjs" setup --owner "대표님" [--skilldb "C:/…/현황관리DB.xlsx"]
   ```
   직원 목록·팀 이름·색·목적은 직원 `.md`의 description에서 초안을 만들고, 직원에게 일을 가장 많이 맡긴 프로젝트 폴더를 '팀장 세션'으로 잡는다. 결과를 그대로 보여 준다.
5. 켜고 창을 연다: `ctl.mjs start` (처음에는 대화 기록을 다 읽느라 1GB당 20초쯤 걸린다).
6. 무엇을 볼 수 있는지 세 줄로 안내하고, 다음부터는 "스킬팀 현황 알려줘"처럼 말하면 된다고 알린다.

설정은 `~/.agent-mission-control/config`(profiles.json·budget.json·skilldb.json)에 저장돼 스킬을 새 판으로 바꿔도 남는다. 직원이 새로 생기면 `setup`을 다시 돌리면 새 직원만 더한다.

## 요청 → 명령

| 사용자가 이렇게 말하면 | 명령 |
|---|---|
| 관제판 열어줘 / 대시보드 켜줘 | `start` (이미 켜져 있으면 창만 연다: `open`) |
| 스킬팀 현황 / 요즘 어때 / 비용 얼마 썼어 | `status --range 7d` (오늘 `today`, 30일 `30d`, 이번 달 `month`, 전체 `all`) |
| 직원별로 보여줘 / 누가 일하고 있어 | `staff` |
| 어떻게 하면 더 잘 운영할까 / 제언 | `advice` |
| 알림 있어? / 알림 다 읽음 | `alerts` / `alerts --read all` |
| 월 예산 500달러로 / 보고서팀 예산 20달러 | `budget --monthly 500` / `budget --staff report-manager=20` (`budget`만 쓰면 지금 값) |
| 리포트 PDF로 저장 / 이번 달 보고서 | `report --range month --open` |
| 스킬 사용 현황 엑셀로 | `export-skills --range 30d` |
| 스킬 점검해줘 | `skills` |
| 보고서팀을 Sonnet으로 / 모두 Opus 5.5로 | `model report-manager sonnet` / `model all claude-opus-5-5` (`default`면 원래대로) |
| 새 직원 반영 / 부르는 이름 바꿔 | `setup` / `setup --owner "팀장님"` |
| 서버 꺼줘 | `stop` |
| 3D 사무실도 쓰고 싶어 / 승인 대기가 안 보여 | 아래 '3D 사무실(선택)'대로 안내만 한다 |

## 3D 사무실(선택)

사무실 라이브 탭의 3D 화면과 '승인 대기' 감지는 다른 개발자가 만든 무료 오픈소스 **claude-3d-frog-office**(https://github.com/d-onworks/claude-3d-frog-office, MIT)가 있어야 보인다. 이 스킬에는 들어 있지 않다.

- 없어도 관제판은 대화 기록만으로 모든 기능이 돈다. 사무실 라이브 탭에는 지금 일하는 직원 카드가 나온다.
- 사용자가 원하면 저장소 주소를 알려 주고, **설치할 때 Claude Code 설정(`settings.json`)에 훅을 넣는다**는 점을 먼저 말한다. 설치는 그 저장소의 README 안내를 따르게 한다.
- 이 스킬이 먼저 나서서 설치하거나 `settings.json`을 고치지 않는다. 설치되어 있으면 관제판이 저절로 찾아 연결한다(기본 포트 4777).

## 지킬 것

- 결과는 명령 출력을 바탕으로 짧게 정리해 전하고, 대시보드 주소를 함께 준다. 숫자를 지어내지 않는다.
- 비용은 **Claude API 단가로 계산한 환산값**이다. 구독 요금제의 실제 청구액이 아니라는 것을 처음 한 번은 말한다.
- **예산 바꾸기·알림 모두 읽음·직원 모델 바꾸기**는 사용자가 그렇게 해 달라고 했을 때만 한다. 모델은 바꾸기 전에 대상 직원과 값을 한 줄로 확인받는다. 모델 변경은 새 Claude Code 세션부터 적용된다고 알린다.
- 리포트·엑셀은 저장한 파일 경로를 그대로 알려 준다.
- 운영 제언은 기록으로 뽑은 제안이다. 실행(예: 직원 모델 바꾸기)은 사용자가 고른 것만 한다.
- 대화 기록의 내용(요청 글·명령)을 필요 이상으로 옮겨 적지 않는다. 대시보드도 명령 원문은 숨기고 사람이 쓴 설명만 보여 준다.

## 대시보드에서 볼 수 있는 것

- **관제판**: 핵심 숫자, 비용·토큰 흐름, 실시간 활동, 운영 제언, 직원 카드(지금 하는 일·모델·이번 달 예산), 최근 작업, 스킬 사용 순위
- **워크플로**: 사용자 → 팀장·다른 세션 → 직원 → 스킬 흐름 지도, 실행 기록 → 단계 타임라인(응답·도구마다 걸린 시간·토큰·비용)
- **스킬 DB**: 스킬별 호출·마지막 사용·확인할 점, 사용 현황 엑셀 내보내기
- **사무실 라이브**: 지금 일하는 직원 카드. 3D 사무실(선택, 따로 설치)과 연결되면 세션별 상태·승인 대기·3D 화면(새 창)
- **🔔 알림·예산**, **📄 리포트**(A4, 인쇄·PDF 저장)

## 문제가 생기면

- `ctl.mjs doctor` 결과로 원인을 찾는다.
- 서버가 안 켜짐: 로그 `~/.agent-mission-control/server.log`를 확인한다. 포트가 겹치면 `PORT=4791`.
- 새 판으로 바꾼 뒤에는 `start`가 예전 판 서버를 끄고 새 판으로 다시 켠다.
- 직원이 0명: `~/.claude/agents/`에 직원 `.md`(머리에 name·description)가 있어야 한다.
- PDF 바로 저장 실패: Chrome·Edge가 없을 때다. 리포트 창의 '인쇄 · PDF로 저장…'으로 저장하게 안내한다.
- 처음부터 다시: 서버를 끄고 `~/.agent-mission-control/cache.json`을 지우면 기록을 다시 읽는다(설정은 그대로).
- 지우기: 서버를 끄고 이 스킬 폴더와 `~/.agent-mission-control` 폴더를 지운다.
